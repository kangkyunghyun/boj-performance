# 이슈 생성

## 제목과 본문

- 제목은 짧은 한국어 명사구다. 변경 목록이나 배경을 제목에 넣지 않는다. 예: `채점 현황 카드 미표시`, `메모리 분포 구간 표시`.
- 템플릿 접두사(`[BUG] `, `[FEAT] `)는 템플릿의 `title` 값을 그대로 쓴다.

| 이슈 | 템플릿 | 라벨 |
|---|---|---|
| 동작 오류, 표시 안 됨 | `.github/ISSUE_TEMPLATE/bug_report.md` | `bug` |
| 새 기능, 개선 | `.github/ISSUE_TEMPLATE/feature_request.md` | `enhancement` |
| 그 밖(문서, CI, 정리) | 없음. 본문을 직접 씀(배경, 할 일, 확인 방법) | 없음 |

- 템플릿을 쓰면 파일을 읽고 머리글 구조를 유지한 채 칸을 채운다. HTML 주석 안내문은 지운다. 모르는 칸은 비워 두지 말고 "확인 안 됨"이라고 쓴다.
- 동작이나 BOJ 계약이 바뀌는 이슈면 본문 끝에 "스펙 영향" 절을 두고 바뀔 `docs/spec` 절을 적는다. 예: `4-1-4 결과 표 읽기`.
- 본문에 비밀값, 쿠키, 다른 사용자의 개인 정보를 넣지 않는다.

## 작업 흐름

1. `gh auth status`와 `gh repo view --json nameWithOwner`로 대상 레포를 확인한다.
2. 같은 내용의 열린 이슈가 있는지 `gh issue list --state open --search "<핵심어>"`로 찾는다. 있으면 새로 만들지 않고 그 번호를 알린다.
3. 본문을 임시 파일에 실제 줄바꿈으로 쓴다.
4. `gh issue create --title "<제목>" --body-file <본문 파일> [--label <라벨>]`로 만든다. 템플릿 라벨이 레포에 없어서 실패하면 라벨 없이 다시 만들고 그 사실을 보고한다.
5. `gh issue view <번호> --json number,title,url,labels`로 결과를 확인한다.

## 금지

- 제목만 보고 템플릿 칸을 지어내지 않는다. 재현 주소, 브라우저 버전처럼 모르는 값은 "확인 안 됨"으로 둔다.
- 생성 응답이 불확실할 때 바로 다시 만들지 않는다. 먼저 목록을 조회해 중복을 막는다.

## 완료 보고

이슈 번호, 제목, URL, 라벨, 쓴 템플릿을 보고한다.
