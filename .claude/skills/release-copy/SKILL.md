# 릴리스 문구 쓰기

릴리스 노트를 사용자 언어로 다시 쓰는 일이다. 옮겨 붙이지 않는다. 두 원본을 제자리에서 고치고 매번 새로 짓지 않는다.

| 문서 | 쓰는 곳 | 독자 | 릴리스마다 |
|---|---|---|---|
| `docs/copy/1-1-STORE-LISTING.md` | Chrome·Whale·Firefox 설명란 | 설치를 고민하는 사람 | 변경 목록 없음. 계속 알릴 기능만 `[주요 기능]`·`[편의 기능]`에 한 줄 |
| `docs/copy/1-2-COMMUNITY-POST.md` | BOJ 게시판 홍보 게시판 | BOJ Performance를 모르는 사람 | 변경 목록 없음. 계속 알릴 기능만 목록에 한 줄. 지표 확인 |

- 두 글 모두 변경 목록을 두지 않는다. 변경 내용은 랜딩 업데이트 소식, GitHub Release, Firefox 버전 노트가 `docs/releases/v<버전>.md`에서 자동으로 보여준다.
- 홍보글은 게시글 문법으로 쓴다. 첫 문장은 독자가 겪는 불편, 첫 문단 안에 이게 무엇인지, 기능은 `-` 목록에 한 줄씩, 목록 밖은 `~습니다.`체. 대괄호 섹션 제목, 리뷰·Star 요청은 광고로 읽혀 넣지 않는다.
- 한쪽 글을 복사해 다른 쪽에 넣지 않는다.

## 순서

1. 노트를 읽는다. 버전은 `src/manifest.json`이 원본이다.

   ```bash
   VERSION=$(node -p "require('./src/manifest.json').version")
   cat "docs/releases/v$VERSION.md"
   ```

2. 사용자 노출 변경만 고른다. `### Internal`은 통째로 버린다. `Features`, `Fixes`에서도 화면에서 겪는 것만. 기준은 "그래서 내가 뭘 할 수 있는데"에 답하는가다.
3. 그중 계속 알릴 기능만 남긴다. 스토어 글은 `[주요 기능]`·`[편의 기능]`에, 홍보글은 대괄호 제목 없는 기능 목록에 한 줄씩 둔다. 세부 조작은 넣지 않는다. 계속 알릴 기능이 없으면 두 글의 기능 목록은 고치지 않는다.
4. 사용자 문장으로 쓴다.
   - 내부 용어(크롤링, 세션 저장소, 스펙, 워크플로, 리팩터링)를 쓰지 않는다. 동작으로 쓴다.
   - 노트에 없는 항목을 쓰지 않는다. 지어낸 문장이 스토어 심사와 사용자 기대에 남는다.
   - BOJ 요청 수 같은 숫자는 스펙 [2-2-6](../../../docs/spec/2-2-REQUIREMENTS.md#2-2-6-품질-제약)과 맞춘다.
5. 두 문서를 고친다. 1-1은 3단계에서 고른 기능 한 줄만, 1-2는 그 한 줄과 지표만. 제목, 설치 링크 세 개, 홈페이지 링크, 맺음말은 그대로 둔다.
6. 지표를 확인한다. 세는 법은 1-2-2의 표가 원본이다. 공개 페이지에서 지금 확인한 값만 쓰고, 확인 못 한 값이 있으면 그 문장을 뺀다. README 배지나 이전 문구의 숫자를 옮기지 않는다.

## 검증

```bash
# 두 글에 버전이나 업데이트 섹션이 들어갔는가 (0줄)
grep -nE "v[0-9]+\.[0-9]+\.[0-9]+|업데이트\]" docs/copy/1-1-STORE-LISTING.md docs/copy/1-2-COMMUNITY-POST.md

# 게시되는 글에 내부 용어가 새었는가 (0줄)
sed -n '/^```text$/,/^```$/p' docs/copy/1-1-STORE-LISTING.md docs/copy/1-2-COMMUNITY-POST.md | grep -nE "크롤|세션 저장소|sessionStorage|스펙|워크플로|리팩터|커밋"

# 홍보글에 스토어 문법이 들어갔는가 (0줄)
sed -n '/^본문:/,/^```$/p' docs/copy/1-2-COMMUNITY-POST.md | grep -nE "^\[|리뷰|Star"
```

명령으로 안 잡히는 것: 지어낸 항목. 노트와 나란히 놓고 읽는다.

## 하지 말 것

- `### Internal`을 요약해 넣지 않는다.
- 두 글에 변경 목록, 버전 번호, 업데이트 섹션을 넣지 않는다.
- 스토어 대시보드 붙여 넣기와 게시판 게시를 대신하지 않는다. 문서를 고치는 데서 끝내고 사람이 한다.
