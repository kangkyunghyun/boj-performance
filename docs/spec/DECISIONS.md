# DECISIONS

현재 적용 기준은 각 명세에 두고 결정 당시의 내용과 대체 관계는 이 문서에 기록한다.

<br>

### 1 기록 규칙

- 결정 하나를 표 하나로 기록한다. 추가만 하고 지우지 않는다.
- 근거는 커밋이다. 커밋 메시지와 변경 내용에서 확인되지 않는 항목은 행을 두지 않는다.
- 결정이 바뀌면 새 ID로 기록하고 대체 관계를 적는다.

<a id="d-013"></a>

**D-013. 채점 서버를 구분하지 않고 비교**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-21 |
| 상태 | 적용됨 |
| 배경 | BOJ 재개 뒤 결과 표에 채점 서버 `1`(AWS)과 `2`(GCP)가 보인다. BOJ는 두 서버가 세대가 달라 실행 시간을 직접 비교할 수 없다고 안내한다.<br>서버 `1`에는 BOJ 종료 전 기록만 있고 재개 뒤 채점은 모두 서버 `2`다(2026-11-21 실측).<br>같은 서버의 제출로만 거르면, 예전에 푼 인기 문제는 최근 정답 제출이 모두 서버 `2`라 표본이 0건이 된다. |
| 채택 | 채점 서버를 구분하지 않고 모든 정답 제출을 한 표본으로 비교한다.<br>섞인 서버별 개수도 표시하지 않는다. 내 기록을 기준으로 다른 사람의 기록과 비교하는 것이 목적이다. |
| 대안 | 같은 채점 서버의 제출끼리만 비교<br>분포만 보이고 내 위치는 숨김<br>안내 툴팁에 서버별 개수 표시<br>셋 다 검토했으나 채택하지 않음 |
| 영향 | 인기 문제는 시간이 지나며 재개 뒤 기록으로 채워진다.<br>제출이 적은 문제는 두 서버의 기록이 오래 섞인다. |
| 근거 | 사용자 결정(2026-11-21), 이슈 #2 |

**D-015. Firefox 확장 ID를 manifest에 포함**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-21 |
| 상태 | 적용됨 |
| 배경 | 1.0.4까지 저장소의 `manifest.json`에는 Firefox 확장 ID가 없었다. Firefox Add-ons에 올린 1.0.4(ID `{e8f7a9c2-4b1d-4f3e-8a5c-9b2d1e0f3a4c}`, 최소 버전 140)는 Firefox용 manifest를 따로 고쳐 올린 것으로 보인다.<br>#7 자동 배포도 세 스토어에 같은 zip을 써야 한다. |
| 채택 | `browser_specific_settings.gecko`에 AMO 등록 ID, `strict_min_version` `140.0`, `data_collection_permissions.required` `none`을 넣고 같은 manifest를 세 스토어에 쓴다. |
| 영향 | 140 미만 Firefox는 업데이트를 받지 못한다. AMO의 1.0.4와 같은 조건이다.<br>Chrome, Whale은 이 키를 쓰지 않으며 확장 관리 화면에 경고를 보일 수 있다. |
| 이전 동작 | 저장소 manifest에 Firefox ID 없음 |
| 근거 | 사용자 결정(2026-11-21) |
