| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-21 |
| 상태 | 적용됨 |
| 배경 | BOJ 재개 뒤 결과 표에 채점 서버 `1`(AWS)과 `2`(GCP)가 보인다. BOJ는 두 서버가 세대가 달라 실행 시간을 직접 비교할 수 없다고 안내한다.<br>서버 `1`에는 BOJ 종료 전 기록만 있고 재개 뒤 채점은 모두 서버 `2`다(2026-11-21 실측).<br>같은 서버의 제출로만 거르면, 예전에 푼 인기 문제는 최근 정답 제출이 모두 서버 `2`라 표본이 0건이 된다. |

|---|---|

| 대안 | `chrome.storage.session`: content script에 기본으로 열려 있지 않아 백그라운드 서비스 워커를 새로 두고 접근 수준을 바꿔야 하고 Firefox 동작이 다를 수 있음. 이슈 본문의 안이었으나 택하지 않음<br>`chrome.storage.local` 영구 저장, 표본 1000건 확대: 사용자가 "서버 없는 확장이 데이터를 쌓아 두는 건 과하다"며 택하지 않음 |

| 이전 동작 | 조회 결과를 저장하지 않고 페이지를 열 때마다 처음부터 받음<br>표본 조회가 모두 끝난 뒤 한 번 그림 |

**D-018. 언어 필터가 없으면 내 가장 최근 정답 제출의 언어로 비교**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-22 |
| 상태 | 대체됨([D-024](#d-024)) |
| 배경 | 언어 필터 없이 채점 현황을 열면 모든 언어의 정답 제출과 비교했다. 언어마다 실행 시간과 메모리 차이가 커서 섞인 비교는 의미가 작다. |
| 채택 | 언어 필터가 없으면(`language_id=-1` 포함) 내 정답 제출 첫 페이지에서 가장 최근 정답 제출의 언어를 비교 언어로 쓴다. 내 기록은 그 언어의 제출 가운데 고르고 표본은 그 언어의 `language_id`로 받는다. 요청 수는 그대로다.<br>언어 이름은 결과 표 언어 셀의 첫 부분이고, 현재 페이지 언어 선택의 `option` 글자와 같으면 그 값을 쓴다. 맞는 `option`이 없으면 모든 언어로 비교하고 "모든 언어 기준"을 보인다.<br>성능 카드 위 한 줄에 비교 언어와 내가 정답을 낸 다른 언어 링크를 둔다. 안내 툴팁의 언어 줄은 뺀다. |
| 영향 | 언어 선택에 없는 언어(2026-11-22 실측 `C++20` 등)로 최근에 풀었으면 모든 언어로 비교한다.<br>언어 필터 없이 연 페이지와 그 언어 필터로 연 페이지가 같은 표본 저장 키를 쓴다. |
| 이전 동작 | 언어 필터가 없으면 모든 언어의 제출로 비교<br>안내 툴팁 둘째 줄에 언어 필터의 언어 이름 |
| 근거 | 사용자 결정(2026-11-22), 이슈 #4 |

**D-019. 서로 다른 값이 30개를 넘으면 분포를 구간으로 묶음**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-22 |
| 상태 | 채택 |
| 배경 | 값마다 막대를 두면 서로 다른 값이 많은 문제에서 막대가 빽빽해 분포를 읽기 어렵다. 막대 툴팁의 `명`은 실제로는 제출 건수였다. |
| 채택 | 서로 다른 값이 30개 이하이면 값마다 막대를 둔다. 넘으면 95번째 백분위수를 넘는 값을 맨 오른쪽 막대(`≥ {경계}`) 하나로 모으고 나머지를 1·2·5×10^k 폭의 구간 20~30개로 나눈다.<br>상위 비율은 묶기 전 값으로 계산한다. 내 값이 표본에 없을 때 1건을 더하는 규칙([D-002](#d-002))은 구간에도 적용한다.<br>막대 툴팁은 `{막대 이름} · {제출 수}건`이다. |
| 영향 | 구간으로 묶이면 내 값이 든 구간 전체가 강조된다. 같은 구간 안의 위치는 상위 비율로만 보인다. |
| 이전 동작 | 서로 다른 값마다 막대 하나<br>막대 툴팁 `{제출 수}명` |

| 대안 | jsdom으로 결과 표 HTML 파싱까지 확인: 의존성이 생겨 택하지 않음<br>파싱 함수를 DOM과 분리하도록 확장 코드를 고치는 안: 테스트를 위해 구조를 바꾸지 않기로 해 택하지 않음 |
| 영향 | 결과 표 읽기, 언어 이름과 언어 필터 대응, 카드와 차트, 테마는 계속 브라우저에서 확인한다. |

| 날짜 | 2026-11-22 |
| 상태 | 채택 |
| 배경 | 사용자가 릴리스 노트를 볼 곳이 없었다. GitHub 자동 릴리스 노트는 PR 제목 목록이라 되합치기 PR까지 들어갔고, Firefox 버전 노트는 비어 있었다. LinKHU는 노트 파일 하나로 GitHub Release, 랜딩, AMO 노트를 맞춘다. |
| 채택 | 버전별 노트 파일(Features, Fixes, Internal)을 release·hotfix 브랜치에서 쓰고, 릴리스 워크플로가 그 파일을 Release 본문으로 쓴다. 파일이 없으면 실패한다.<br>랜딩 페이지를 GitHub Pages에 두고 GitHub Releases API로 최근 노트를 보인다. Firefox 제출은 Internal을 뺀 노트를 버전 노트로 보낸다.<br>확장에는 manifest `homepage_url`만 둔다. 성능 카드에 업데이트 소식 링크와 새 버전 표시를 두지 않는다. |
| 대안 | 성능 카드에 업데이트 소식 링크나 새 버전 표시: 사용자가 두지 않기로 함<br>LinKHU 랜딩 구성(서비스 검색, 피드백 등) 그대로: 한 화면짜리 확장이라 소개, 캡처, 스토어 링크, 업데이트 소식만 둠 |
| 영향 | 1.1.0 Release 본문을 노트 파일로 바꿨다.<br>랜딩 배포와 `homepage_url`은 다음 릴리스의 `main` 병합으로 함께 나간다. |
| 이전 동작 | GitHub 자동 릴리스 노트<br>Firefox 버전 노트 없음<br>manifest에 `homepage_url` 없음 |

|---|---|

| 배경 | 재오픈한 BOJ는 `Sec-Fetch-Mode: cors` 요청에도 결과 표를 준다. curl로 `cors`와 `navigate` 헤더를 보냈을 때 둘 다 결과 20행이었고, 브라우저에서 규칙의 적용 주소 밖(`//status`)으로 기본 헤더 그대로 보낸 페이지 안 조회도 20행이었다. |

**D-024. 비교 언어는 언어 필터만 따르고, 표본을 다 받은 뒤 한 번 그림**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-27 |
| 상태 | 채택 |
| 배경 | D-018로 언어 필터가 없으면 내 가장 최근 정답 제출의 언어로 비교하고 카드 위에 비교 언어 줄을 뒀다. 사용자는 원래 의도가 BOJ 채점 현황의 언어 선택을 그대로 따르는 것이라고 했다.<br>D-017로 저장한 표본이 없으면 첫 페이지(약 20건)로 먼저 그렸다가 조회가 끝나면 다시 그렸다. 이미 보인 숫자가 바뀌는 것보다 다 받은 뒤 한 번 보이는 편이 낫다고 했다. |
| 채택 | 비교 언어는 언어 필터 그대로다. 없으면(`-1` 포함) 모든 언어로 비교하고 내 기록도 모든 언어의 정답 제출 가운데 고른다. 비교 언어 줄과 다른 언어 링크는 없다.<br>표본 조회가 끝날 때까지 카드에 스켈레톤을 보이고 한 번만 그린다. 저장한 표본이 있어도 새 정답 제출을 받아 붙인 뒤 한 번 그린다. 화면 낭독기에는 스켈레톤 동안 "분석 중..."을 읽힌다. |
| 영향 | 언어 필터 없이 열면 여러 언어가 섞인 분포와 상위 비율이 보인다.<br>같은 탭에서 다시 열 때 저장한 표본을 바로 보이지 않고 새 제출 조회(보통 요청 1회)를 기다린다.<br>결과 표의 언어 셀을 읽지 않는다. |
| 이전 동작 | [D-018](#d-018)의 최근 언어 비교와 비교 언어 줄<br>[D-017](#d-017)의 첫 페이지 먼저 그리기와 저장한 표본 바로 보이기 |
| 근거 | 사용자 결정(2026-11-27), 이슈 #41 |
