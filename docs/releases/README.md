# 릴리스 노트

`v<버전>.md` 하나가 그 버전 노트의 원본이다. release·hotfix 브랜치에서 버전을 올릴 때 함께 쓴다. 쓰임과 거르는 규칙은 [6-1](../spec/6-DEPLOYMENT.md#6-1-배포-경로)에 있다.

| 절 | 내용 | 보이는 곳 |
|---|---|---|
| `### Features` | 사용자에게 보이는 새 기능 | GitHub Release, 랜딩, Firefox 버전 노트 |
| `### Fixes` | 사용자에게 보이는 수정 | GitHub Release, 랜딩, Firefox 버전 노트 |
| `### Internal` | 배포, 테스트, 문서 같은 내부 변경 | GitHub Release에만 |

- 없는 절은 쓰지 않는다. 문법은 절 제목, `- ` 목록, `` `코드` ``만 쓴다. 랜딩이 이것만 그린다.
- PR 제목을 옮기지 않는다. 사용자가 무엇이 달라졌는지 알 수 있게 쓴다. Features와 Fixes는 "~합니다" 문장, Internal은 짧은 명사형.
- 앞 버전 이후 스토어에 나가지 않은 변경도 이번 노트에 넣는다. 예: 1.0.5는 Chrome 웹 스토어에 공개되지 않아 도메인 수정을 1.1.0 Fixes에 넣었다.
